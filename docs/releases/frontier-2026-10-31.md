## Bring-up ladder — do not skip dependency gates

1. **Freeze source contract:** review strict JSON authority parsing, peer
   observer redirect behavior, GitHub create-once/422 handling and source
   compatibility; acquire independent reviewer/owner admission. Preserve the
   original source and failure evidence.
2. **Close peer lifetime model:** prove generation supersession rejects stale
   operations before replay and mutation across distinct old/replacement
   processes and shared state; test cancellation/drain, authority substitution,
   skew, and duplicate or reordered requests. Model-check any abstract
   invariants against explicit code/test correspondence.
3. **Qualify canary admission offline:** render intended Docker Compose v2
   configuration as JSON and compare to the genuine original v0.0.1 release
   receipt with a strict fail-closed checker. Never interpret a synthetic
   manifest or handwritten fixture as actual Compose validation.
4. **Qualify exact new release candidate:** on reviewed merged main, run
   native amd64/arm64 unit/race/conformance, static Go builds, scratch OCI
   smoke, independent receipt verification, and a newly authorized real
   publication only if a new image is actually required.
5. **Qualify target-native read-only preflight:** use supported TrueNAS App
   and rootless OCI/Quadlet lifecycle contracts; preserve credentials and
   all existing host state. This is not permission for a target mutation.
6. **Prove additive installation and reversible migration:** inventory legacy
   profiles, preserve durable request/claim/receipt state, rehearse recovery
   and rollback, and obtain separately reserved authority before mutating
   deployment or switching the live Agent Dispatch control path.
7. **Admit one bounded operational integration loop only after acceptance:**
   verify a legitimate request, single claim, native observation, terminal
   receipt, independent reconciliation, then decide later peer activation
   and eventual legacy retirement under separate owner authority.

## Release blockers, and what can run independently

The first three steps and CI/documentation/dependency hygiene can run in
parallel with distinct writers. Actual image publication requires accepted
source and owner release authority. Target HIL requires exact image and
approved preflight scope. Legacy cutover requires HIL, state preservation,
rollback rehearsal and explicit acceptance; it is necessarily sequential.

No automatic release, new credentials, remote listener changes, live peer
activation, host mutation, or legacy retirement is authorized by this status
file. Git and private DLE own source and verified structured evidence;
target-sensitive binaries belong in private controlled storage.
